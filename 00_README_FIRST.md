# SafetyPool Code and Results Package

This artifact accompanies the paper **“SafetyPool for Collision-Aware Deep
Reinforcement Learning.”** It is organized as an IEEE-style reproducibility
package: documentation appears first, source code is separated from data, raw
results are immutable inputs, processed tables and figures are regenerated by
one analysis entry point, and checksums verify the delivered files.

> **Scope.** This package contains the complete **MetaDrive** evaluation used
> for the paper’s 23-seed comparison. It does not contain Highway results.

## What is included

- SafetyPool policy source in both unchanged archival and reusable modular
  forms, plus baseline-training Python source.
- Raw CSV/JSON outputs for all 23 matched training seeds.
- Three canonical baselines: Epsilon-Greedy DQN, NoisyNet DQN, and DQN + RND.
- Per-seed and aggregate results for the two confirmatory metrics:
  - **Collision RMST (steps), higher is better**
  - **Maximum-step completion rate, higher is better**
- Fifty publication-ready graphs (46 per-seed and four aggregate), each in
  300-dpi PNG and vector PDF formats.
- Seed-level metrics, IQM summaries, paired Wilcoxon tests, Holm-corrected
  p-values, validation records, and SHA-256 checksums.

The 23 seeds are:

```text
3, 5, 7, 9, 13, 17, 19, 29, 31, 33, 38, 42, 45, 48, 54, 63, 67, 69, 77, 85, 94, 108, 111
```

Each method has 300 frozen-policy test episodes per seed, using scenario seeds
100000–100299 and a 500-step episode limit. The package therefore validates
92 seed–method result files and 27,600 test episodes.

## Name mapping

The paper-facing method name is **SafetyPool**. Its original experiment files
and policy source use the internal identifier **`Karthikeya27adv8`**. This
identifier has been retained inside source files and provenance fields so that
the packaged results remain traceable to the exact run. It does not denote a
different method.

## Quick start

From the package root:

```bash
python -m pip install -r 03_configuration/requirements.txt
python -u 02_source_code/analysis/generate_ieee_results.py
```

Or use the supplied runner:

```bash
bash 02_source_code/runners/regenerate_results.sh
```

The analysis performs strict completeness checks before generating any
statistics or figures. A successful run ends with a `PASS` message and writes:

- `04_data/processed/` — seed-level metrics, aggregate metrics, tests, and
  completeness records;
- `05_results/comparisons/seed_<N>/` — two graphs and a metric table for every
  seed;
- `05_results/comparisons/aggregate/` — all-seed and IQM graphs for both
  metrics;
- `05_results/tables/` — paper comparison and paired-test tables;
- `06_checksums/validation_report.json` — machine-readable validation summary.

## Important artifact notes

- Raw result files are included; neural-network weight files are omitted
  because they are not required to reproduce the packaged statistics or
  figures and would substantially enlarge the artifact.
- The included raw CSV/JSON files are treated as immutable experimental
  outputs. Regeneration writes only to `04_data/processed`, `05_results`, and
  `06_checksums/validation_report.json`.
- No software license was supplied with the experiment archive. Redistribution
  and reuse therefore remain subject to permission from the authors.
- IEEE does not mandate one universal code-directory hierarchy. “IEEE-style”
  here means a reviewer-oriented reproducibility layout with explicit
  provenance, protocol, data, code, results, and integrity checks.
